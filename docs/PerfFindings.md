# 計測結果と課題

作成: 2026/10/20(再作成: 2026/10/22) / 作成者: 24CU0110 大川翔生
対象: 3台の PC で取った記録(2026/10/19〜20)。記録はプロジェクト直下の `PerfRecords\`。計測の仕組みと使い方は `Perf.md`、改良候補の全体は `CurrentStateAnalysis.md`。

計測結果から出た問題点と修正点の一覧と、その根拠の実測値。計測するたびに、状況と数値を更新する。

- **確認**: `実測`(記録の数値で確認した)、`コード`(ソースを読んだ)、`推定`(数値やコードからの推測)、`未確認`。
- **優先**: 高 = 展示の連続稼働で、止まる・崩れる / 中 = 修正や判断が要る / 低 = 気づいた点。
- PC の記録は混ぜない。FPS・VRAM・メモリの数値は PC ごとに違う。基準以外の条件は、1回ずつの記録で、ばらつきは分からない。

## 結論

1. **周回でメモリと VRAM が増える。主因は DLSS**(実測)。止めると `private_mb` の増加が約98〜99%減る(3060 Ti +660 → +10、展示用 +813 → +13)。映像(Timeline)は主因でない。
2. **DLSS を全部止めても解決にならない。** 走行中の FPS が約3割下がる(86 → 67、75 → 51)。
3. **`maponly`(Map のカメラだけ DLSS を残す)は、増加を約半分以下にし、走行中の FPS を保つ。** ただし Opening・Menu の FPS が下がる(2台で一致)。増加は残るので、上限に達するのが遅れるだけ。
4. **本命の対策(`unloadoff`: 破棄する前に DLSS を止める)は、どの PC でも未測定。**
5. 展示用 PC(VRAM 16 GB)は、基準が10周で VRAM 99% に達したが、FPS は崩れなかった。3060 Ti(8 GB)は、VRAM が上限に達した6周目から崩れた。展示用 PC の10周を超える記録はない。

## 詳細

### A-1 メモリ・VRAM の増加と FPS の崩れ

- DLSS は全シーンのカメラで有効(`allowDeepLearningSuperSampling`)。Map・Opening・Menu・Splash・Load に1台ずつ、Result に2台(1台は `ResultState` が実行時に作る)。シーンを読み込むたびにカメラが作られ、破棄される(コード)。
- Intro と Racing は同じ Map なので、Map のカメラは1周に1台。Map 以外のカメラは、周の途中で何度も作られ、破棄される(`Player.log` の `[PerfAutoLap]` の累計では、1周あたり約8〜9台)。
- 残る増加の内訳(`base` と `maponly` の差、3060 Ti): Map のカメラが約214 MB/周(約3分の1)、それ以外のシーンのカメラが約446 MB/周(約3分の2)。1台あたりでは、Map のカメラ約214 MB、それ以外約60 MB で、均一ではない(理由は未特定)。
- HDRP 17.6.0 のソース(読んだ結果): DLSS はカメラごとに状態を持つ。DLSS を無効にしたカメラが次の1フレームを描画すると、その場で解放される。破棄されたカメラは、`BeginFrame` が400回呼ばれた後か、管理用の弱参照が GC で切れた後に解放される。ソースの上では破棄後も数秒で解放されるはずだが、実測ではメモリが戻っていない。**原因は未特定**(解放の呼び出しが遅れているのか、NGX 側で戻らないのか)。`unloadoff` が効くかは、実測するまで分からない。

| 案 | 状況 |
|---|---|
| 破棄の前に DLSS を止める(`unloadoff`) | 未測定。当たりなら、全シーンの DLSS を残したまま直せる。本番用の実装(`DlssSceneGuard` の案)は、まだない。止める処理は、計測用の `PerfAutoLapRunner` にしかない |
| Map のカメラを作り直さず、使い回す | 未調査 |
| 暫定: Map 以外のカメラの DLSS を止める(`maponly`) | 増加は約半分以下。FPS は保たれるが、Opening・Menu が下がる。10周で VRAM が上限に近い |
| DLSS を全部止める | 解決にならない(FPS が約3割下がる) |

### 何を決めるための計測か

- 運用は、1日140〜160プレイ(毎時20人前後 × 7〜8時間)、再起動は手動、走行中の FPS は50以上。

- 過去の展示は、FPS が1桁になるまで気づけなかった(見た目で判断)。3060 Ti の `base` では、50 FPS を割った7周目から、1桁(8.7)になった10周目まで3周ある(実測。旧ビルド)。見た目で待つと、50 FPS を割った状態のプレイが続く。
